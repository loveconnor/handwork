# Harness efficiency research and experiment design

Research checked September 18, 2026. Implementation starts from the repository's frozen ReleaseFast build at the beginning of this task. This work tests engineering hypotheses; it does not promise leaderboard gains.

## Evidence and decisions

1. **Reduce discovery rounds.** [LangChain's controlled-model harness study](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering) reports a bundled 52.8% to 66.5% Terminal-Bench 2.0 improvement and describes upfront environment context, verification, and repeated-failure intervention. This is evidence for experimentation, not an isolated estimate for any individual change. Handwork already supplies cwd, OS, date, and limited Git metadata. Add a bounded paths-only inventory, not another shell bootstrap. Preserve the existing `git_worktree: unknown` meaning: absence of detected changes is not proof of a clean tree.

   The inventory scans at most 256 entries, retains at most 64 paths / 4096 raw path bytes, descends at most two directory levels, and checks a 25 ms elapsed budget between entries. It skips hidden/generated paths and symlinks and encodes filenames as data. Filesystem syscalls themselves are not preemptible by the time budget. It is admitted only in native full-access mode; ask/auto and host-managed workspaces continue through ordinary tools. Manifest contents and commands are not automatically read or executed. Source and test configuration should be read together via existing batch reads. This deliberately narrower implementation avoids bypassing configured file-read rules.

2. **Reduce repeated context.** [Anthropic's context engineering guidance](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) recommends selective retrieval, compact state, and preserving information needed for continuation. Handwork already has output previews, dynamic capability retrieval, and compaction. Add request-only deduplication of successful, byte-identical read/search outputs of at least 1024 bytes, looking back at most 64 messages. Keep the earliest complete body in the actual request and replace only later copies with an explicit reference. Preserve call IDs, status, provenance, durable history, failures, truncated results, and images. Never skip execution of a requested reread; its latest success remains real evidence. This keeps the earlier request prefix stable and avoids introducing summary-model calls. Do not implement general semantic summarization or speculative tool pruning without accuracy evidence.

   Opt-in trace events separate instruction text, conversation text, tool output, tool arguments, private provider replay byte counts, serialized schema bytes, and total serialized request bytes. Response events report provider token/cache counters and elapsed request time. Byte categories are not a tokenizer, complete wire partition, or billing audit. Images/envelopes explain differences. No prompt bodies or credentials are added to these diagnostic events. The normal provider usage ledger remains authoritative. Parsing for schema accounting uses temporary allocations freed after each event, not the turn arena.

3. **Recover and verify.** Detect the last three consecutive tool failures with identical tool name and output since the latest user message. Add a bounded diagnostic instruction to the next already-required request. Successful work, changed errors, user steering, and explicit permission feedback break the streak. The hint grants no authority and explicitly preserves permission refusals. It does not force an additional provider call or interrupt useful edits solely because a file was edited several times. Strengthen normal verification guidance and compaction's treatment of exact failed checks and their actual resolution. The existing runtime still owns cancellation, retries, completion, permissions, and durable state. This is not a claim that a model will always follow the hint or retain every fact.

4. **Broaden evaluation.** [SWE-bench's evaluation guide](https://www.swebench.com/SWE-bench/guides/evaluation/) uses reproducible container environments and test outcomes. [Harbor's custom-agent integration](https://docs.harborframework.com/core-concepts/agents/custom-agents) supports installed CLIs, while [its ACP integration](https://docs.harborframework.com/core-concepts/agents/acp) can use a local registry entry. A protocol implementation alone does not establish a validated benchmark adapter. Local Docker preflight failed because its daemon is unavailable. `harbor_agent.py` supplies an installed-agent adapter accepting a frozen Linux ELF build, explicit API provider/model/effort, and Harbor-managed environment credentials. Its public container validation remains outstanding; no official public-suite score is claimed.

   Expand the existing three development fixtures with three predeclared held-out tasks: bounded concurrent queue execution with failures; atomic tenant-scoped idempotent ledger transfers; chunked JSONL decoding with malformed-record recovery. Each has independent behavioral checks, a broken control, a known-correct control, existing tests, protected files, and an isolated workspace. Hold these out from runtime tuning and report them separately. These are small local tasks, not substitutes for large-repository, multi-language, long-context, or interrupted-session public evaluations. Recovery and compaction behavior also receive deterministic regression checks; short-task benchmark success cannot establish long-horizon performance.

## Measurement plan

- Freeze and hash baseline and candidate executables; preserve implementation and task sources.
- Same model (`gpt-6-astra`), low reasoning, full-access native loop, 600-second wall budget per attempt, fresh sessions/workspaces, serial runs, alternate variant order.
- Two pairs per task for the final six-task pilot. Every attempt counts; no selective reruns or replacement of disappointing results.
- Hidden verifier and benchmark repository inaccessible to the agent, including symlink probes. No build/test workloads overlap scored attempts.
- Report successful-task time, total input/output/cache tokens, provider requests, native calls, sampled process-tree agent RSS, and protected-file violations. Tokens across all attempts include failures. Dollar cost is unavailable for the subscription route; equal dollar budgets are not claimed.
- Treat the target of 20% lower latency with no correctness/token regression as an acceptance target, not an expected result. Report per-task regressions explicitly. Two pairs are insufficient to infer a general ranking or statistical significance.
- Do not change the implementation after examining held-out scores. Further tuning requires a fresh holdout.

## Observed environment limitation

The inherited runner resets provider settings and workspaces, but does not create a pristine personal Handwork profile. Both variants load the user's `unslop` skill and report the same inaccessible compatibility skill directories under the sandbox. Available global context hashes were sampled during the study and will be checked again at completion; these are observations, not a retrospective guarantee of unchanged initial content. Preserve this limitation in comparisons. A future clean-profile study should explicitly control instruction and skill discovery rather than compare these results to a different personalization setup.
